## 1. Executive summary — the findings that change the plan

1. **The keep-list maps onto real code, but with three naming corrections.** The bar
   style on the keep-list ("qsbar") is a *bar style inside the frame*, not a standalone
   bar; "quick settings" is the Super+Escape **control sidebar** under
   `barstyles/qsbar/controlcenter/`; and wallpaper is **not** owned by the shell daemon.
2. **Wallpaper is a separate daemon, `ryogami`** (`ryoku/shell/ryogami/daemon`, own Go
   module, own systemd unit). "Trimmed ryoku-shell" ≠ "wallpaper works": Mei needs
   `ryogami` too, or a substitute.
3. **The Settings app does write Hyprland config — and the writer is not in `hub/`.** The
   generation lives in `ryoku/wm/hyprland` (the WM provider) and is invoked by
   `ryoku-hub`. It writes `settings.lua`, `rebinds.lua` and `user_edits/hypr/*.lua`, then
   runs `hyprctl reload`. Disabling this means disabling the hub's WM verbs — a code
   change, not a config flag. **This directly collides with your live Lua config.**
4. **Installed Hyprland is fine: 0.56.2 ≥ 0.55, and your session already runs Lua**
   (`~/.config/hypr/hyprland.lua`). But your config is HyprMod-shaped
   (`hyprland-gui.lua` "Generated by HyprMod", `config/*.lua`), which is *not* Ryoku's
   `modules/*.lua` layout — so Ryoku's Hyprland tree must never be laid over yours.
5. **Nothing for the look is installed.** Every font the UI hardcodes (Space Grotesk,
   Fraunces, SpaceMono/JetBrainsMono Nerd, Inter, Noto CJK/emoji, Material Symbols)
   is missing; `fc-match` falls back to Nimbus. Fonts are a Phase 4 approval item, not a
   "should be there".
6. **Build toolchain is incomplete:** `go` and `cmake` are missing; `ninja` is present.
   All Go components and the C++ Blobs plugin need them. `uv` is also missing and
   `ryoku-shell`'s PKGBUILD lists it as a runtime depends.
7. **Motion is centralised *enough* to preserve it cheaply.** Shell motion lives in one
   file, `services/Motion.qml`, behind a `dur()` scaling hook; app-level motion is
   `ui/Singletons/Tokens.qml`. But there are also per-module `Motion.qml` singletons and
   hundreds of literal durations — full centralisation is **not** free (see §8).
8. **The write surface is mostly XDG-redirectable** — the shell resolves config/cache/state
   from `XDG_CONFIG_HOME`/`XDG_CACHE_HOME`/`XDG_STATE_HOME`, so Mei's launcher can confine
   it. Two absolute leaks are **not** XDG-redirectable: `/tmp/ryoku-hub.lock` and
   `/run/polkit/agent-helper.socket` (see §14).
9. **The daemon phones home.** `ryoku-shell` calls weather/calendar/lyrics/Deezer/iTunes
   endpoints; none are on the keep-list and each must be dropped or neutered.
10. **Licence: GPL-3.0-or-later.** Redistribution obligations attach to anything Mei
    ships. Credits to preserve include "QS Bar (Quickshell Rise)".

## 6. Settings (the hub)

### 6.1 Shape

`ryoku-hub` (`hub/backend`, module `ryoku-hub`, `go 1.26.4`) is a **one-shot CLI**, not a
daemon: each invocation runs one verb and prints JSON to stdout (`main.go:16-137`); the only
flag is `--preview` `[REPORTED]`. The UI is a separate Quickshell app, `qs -c hub`
(`hub/quickshell/`), talking to the CLI by exec/file-watch `[REPORTED]`.

It `replace`s two local modules: `ryoku-wm => ../../wm` and
`ryostore => ../../apps/ryostore/backend` `[REPORTED]` — note the second is **not** on disk
and is out of scope; any hub verb touching it is a Phase 4 cut.

### 6.2 The Hyprland write path — **the critical finding**

- The config **generator lives in `ryoku/wm/hyprland`**, the provider — not in `hub/`.
  `apply.go` writes `settings.lua` and `rebinds.lua` into the Hyprland config dir and
  `user_edits/hypr/*.lua` (`grep settings.lua|rebinds.lua ryoku/wm/hyprland/*.go`) `[TESTED]`.
- The provider shells out to `hyprctl` (`session.go:108` region) `[TESTED]` — i.e. it
  **reloads Hyprland** after writing.
- The desktop PKGBUILD comment states the mechanism outright: "the generated
  `settings.lua` loads one only once the user enables it" (plugins) and the Hub's
  Settings > Plugins toggles `settings.lua` `[READ]`.

**Consequence for Mei:** "Settings must never write Hyprland config" cannot be satisfied by
config alone. Phase 4 must (a) not build/ship the wm provider's write verbs for Mei's hub,
(b) grep-assert no `settings.lua`/`rebinds.lua`/`hyprctl` path is reachable from Mei's
Settings, and (c) test with `verify-untouched` after every Settings interaction.

## 10. Hyprland integration and version requirement

### 10.1 Integration style

- Nothing outside `ryoku/wm/` may name a compositor; consumers ask the provider for
  capabilities — `docs/compositors.md` `[READ]`. The shell therefore does **not** call
  `hyprctl` directly; it talks to `ryoku-wm-<provider>` (eleven verbs: `caps`, `state`,
  `watch`, …) `[READ]`.
- The provider binary is `ryoku-wm-hyprland`, shipped by `ryoku-desktop-hyprland`, and a QML
  module `ryoku/wm/hyprland/qml` is imported by the shell `[READ]`.
- `ryoku-shell`'s PKGBUILD depends on `quickshell ffmpeg wayland jq uv` `[TESTED]`.

### 10.2 The Lua / version requirement, versus what you run

| Fact | Evidence |
|---|---|
| Ryoku authors Hyprland config in **Lua** (`ryoku/hyprland/hyprland.lua` + `modules/`) | `ls ryoku/hyprland/` `[TESTED]`; AGENTS.md rule 2 `[READ]` |
| Stock Hyprland loads `hyprland.lua` natively from **0.55+** | upstream README `[READ]` |
| **You run `hyprland 0.56.2-4` — compatible** | `pacman -Q` `[TESTED]` |
| **Your session already runs Lua**: `/home/mei/.config/hypr/hyprland.lua` requires `config/{variables,env,autostart,monitors,settings,keybinds}.lua` | `cat` `[TESTED]` |
| Your config is **HyprMod-shaped**: `hyprland-gui.lua` = "Generated by HyprMod"; settings live in `~/.config/hypr/config/settings.lua` | `cat` `[TESTED]` |
| Your `hyprland.lua` does **not** require `~/.config/hypr/settings.lua` (the file Ryoku's generator writes) | `cat` `[TESTED]` |

**Conclusion:** Hyprland-version-wise, Ryoku's Lua desktop would run here. Ryoku's
`ryoku/hyprland/` tree is a *replacement* config, not an overlay, and must **never** be laid
over your `~/.config/hypr/` (different layout, and it would take over your keybinds).
Your Hyprland config is out of scope per AGENTS.md; this audit only records the seam.
